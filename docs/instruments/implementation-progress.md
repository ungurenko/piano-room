# Три фортепиано: внедрение

Пользователь выбрал Osiris Piano, Headroom Piano и Fuchs & Möhr из исследования и явно попросил внедрить их. Работа выполняется в существующей ветке codex/builtin-reverb; старые незакоммиченные изменения сохраняются.

## Решения

- Osiris/Headroom используют SFZ с условиями педали и динамическим релизом. Проверенная EXS-конвертация теряет условия по CC: этот вариант отброшен.
- Выбран строгий realtime C++ проигрыватель необходимых SFZ-команд, MIT WAVReader/SampleBuffer из SFZPlayer и MIT dr_flac. Исходные FLAC сохраняются без потерь и без увеличения установочного размера. Физическую модель инструмента не изобретаем; проигрываются исходные записи.
- Fuchs остаётся SF2 и играет через Apple AUSampler, общий с Salamander. При выборе каждого SF2 загружается именно его банк; Salamander ищется явно по имени.
- В каталоге 132 инструмента, 9 избранных. Старые горячие клавиши 1–6 сохраняются, новые 7–9. Новые три показываются сразу под Salamander.
- Загрузка библиотек идёт на очереди звука при остановленном движке; во время загрузки есть индикатор, новые ноты не накапливаются. Ошибки показываются явно.
- Все перезапуски восстанавливают выбранный SF2/GM и сбрасывают голоса SFZ без потери сэмплов. Обязательны тесты сохранения звучания Salamander и остальных инструментов.

## Владение задачами

- prepare_three_pianos: Tools/download-pianos.sh, prepare-pianos.py, Resources/Instruments, build/library-*; нормализация SFZ сохраняет педаль/CC64/67/70 и авторские настройки, убирает только GUI и фиксированные настройки обрабатывает явно.
- sfz_playback_engine: PianoDSP.h/.cpp, ThirdParty/SFZPlayer/dr_flac, Tools/piano_dsp_test.cpp; SPSC MIDI, заранее выделенные голоса, реальные библиотеки, ASan/UBSan, benchmark.
- three_pianos_catalog_ui: модель, каталог, InstrumentsPanel/AllInstrumentsView/StageView и catalog_test — готовы, отдельный swiftc прошёл.
- Корневой агент: Swift source node, AudioEngine/AppState, сборка, интеграционные тесты, документация/лицензии, проверка приложения и установка.

## Результат — 2026-11-15

Три инструмента внедрены, Release для arm64 и x86_64 собран и установлен в `/Applications/Piano Room.app`. Установленный исполняемый файл совпадает со сборкой. Приложение оставлено на Osiris, буфер 128, прежняя громкость и эффекты сохранены.

- Debug: 14 тестов прошли. Release с `ENABLE_TESTABILITY=YES`: 15 тестов прошли, включая новый сценарий смены сохранённого Osiris на Headroom во время начальной загрузки. Обычная Release-сборка после проверок тоже прошла.
- `Tools/run-tests.sh`: все 6 групп прошли, включая MIDI, каталог, хорус, реверб и реальные Osiris/Headroom. После последней проверки числа каналов WAV проигрыватель повторно проверен на двух настоящих библиотеках.
- Офлайн-рендер через AVAudioSourceNode подтверждает разные записи Osiris/Headroom, реакцию на силу нажатия, точное сохранение формы сигнала после stop/start и сохранение прежней библиотеки при неудачной загрузке. Нативный Fuchs и прежний Salamander сохраняют форму сигнала после перезапуска.
- Независимая проверка нашла одну подтверждённую гонку: выбор во время первой загрузки терялся. Исправлено; отдельный тест воспроизводит этот сценарий и проходит. Проверка агента затем прервалась из-за лимита сервиса, полный независимый аудит не заявляется. Завершающий просмотр выполнил координатор.
- SFZ-ядро прошло ASan/UBSan и проверку отсутствия выделений памяти в обработке. Последний Release-замер: Osiris загрузка 6,77 с, p99 блока 256 кадров 126 мкс; Headroom 1,86 с и 46 мкс при бюджете блока 5.333 мкс. Osiris получает выходной коэффициент 0,35 для запаса громкости.
- В установленном приложении выбраны все три инструмента и нажата «Проверить звук». Журнал общего выхода подтверждает пики: Osiris 0,124; Headroom 0,067; Fuchs 0,181. После смены буфера Fuchs 128→256 дал пик 0,167, Headroom 256→128 — 0,060. Возврат к Salamander дал пик 0,168. Ошибок загрузки в этих сценариях не было.

Ограничения: физическое пианино не подключено, его клавиши/педали и динамики в этом запуске не проверялись. Человеческая оценка звучания не выполнена. Это собственный проигрыватель закреплённых подготовленных SFZ, совпадение с другим SFZ-движком по каждому отсчёту не заявляется. Микрофонный баланс соответствует выбранным авторским настройкам; отдельного интерфейса микрофонов нет. Сэмплы загружаются в память, одновременно активна одна SFZ-библиотека. Музыкальные демофайлы не требовались и не создавались. Публикация и отправка в Git не выполнялись.
